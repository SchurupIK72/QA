## 📋 Шаблоны

### Баг-репорт (bug-report-template.csv)

**Обязательные поля (отмечены *):**
- **ID*** - Уникальный идентификатор бага (формат: BUG-[Section]-[Number])
- **Section*** - Раздел системы (Backend, Frontend, UI/UX и т.д.)
- **Title*** - Заголовок (отвечает на вопросы: Что? Где? Когда?)
- **Steps*** - Шаги воспроизведения
- **Actual Result*** - Фактический результат
- **Expected Result*** - Ожидаемый результат
- **Environment*** - Окружение (браузер, ОС, устройство)
- **Proofs*** - Ссылки на пруфы (скриншоты, видео, логи)

**Дополнительные поля:**
- Opening Date - Дата обнаружения
- Platform - Платформа (iOS, Android, Web и т.д.)
- Status - Статус (Open, In Progress, Reopen, Done, Archive, No bug)
- Severity - Критичность (Critical, Major, Minor, Trivial)
- Priority - Приоритет (High, Medium, Low)
- Developer - Ответственный разработчик
- Pre-condition - Предусловия
- Build - Номер билда
- QA - Ответственный QA
- Additional info - Дополнительная информация
- Bug frequency counter - Счетчик воспроизведений

### Чек-лист регрессионного тестирования (checklist-regression-template.csv)

**Структура:**
- № п/п - Порядковый номер проверки
- Раздел - Раздел тестирования
- Название проверки - Описание проверки
- Статусы по браузерам и платформам:
  - Google Chrome
  - Яндекс Браузер
  - Safari
  - Microsoft Edge
  - Opera
  - FireFox
  - Mobile
- Дата проверки
- Ссылка на баг-репорт (если найден баг)
- Комментарий

**Статусы проверок:**
- `PASSED` - Проверка пройдена успешно
- `FAILED` - Проверка не пройдена (найден баг)
- `SKIPED` - Проверка пропущена (нельзя проверить/серая зона)
- `NOT STARTED` - Проверка не начата

- Монетизация
- Инвентарь и предметы
- Боевая система
- Социальные функции
- События и активности
- Турниры и соревнования
- Уведомления
- Onboarding и туториал
- UI/UX требования
- Сообщения об ошибках
- Валидация данных
- Интеграции
- Офлайн режим
- Производительность
- Безопасность
- Административная панель

## 🚀 Начало работы

### Создание нового проекта

1. Создайте папку для проекта в `projects/`:
```powershell
mkdir projects/[project-name]
mkdir projects/[project-name]/bug-reports
mkdir projects/[project-name]/checklists
mkdir projects/[project-name]/test-data
mkdir projects/[project-name]/docs
```

2. Скопируйте шаблоны из `templates/` в папку проекта:
```powershell
Copy-Item templates/bug-report-template.csv projects/[project-name]/bug-reports/bug-report-[date].csv
Copy-Item templates/checklist-regression-template.csv projects/[project-name]/checklists/checklist-[date].csv
```

3. Заполните документацию проекта в `projects/[project-name]/docs/`

## 📝 Правила оформления баг-репортов

### Структура заголовка
Формат: `[Раздел].[Подраздел].[Описание проблемы]`

**Примеры:**
- `MainPage.Frontend.Отсутствует визуальный элемент на главной странице`
- `Features.Frontend.Ошибка при нажатии на кнопку функции`
- `Gallery.Frontend.Элемент галереи не отображается корректно`

### Шаги воспроизведения
Должны быть максимально подробными:
```
1. Открыть приложение/веб-сайт
2. Перейти в нужный раздел
3. Выполнить действие (нажать на кнопку, ввести данные)
4. Обратить внимание на результат (что произошло неправильно)
```

### Пруфы (Proofs)
Обязательно прикладывать:
- Скриншоты с выделенной проблемной областью
- Видео воспроизведения бага
- Логи (при необходимости)
- Ссылки на билды/окружение

## 🔄 Статусы баг-репортов

| Статус | Описание |
|--------|----------|
| **Open** | Новый баг, еще не взят в работу |
| **In Progress** | Баг в работе у разработчика |
| **Reopen** | Баг переоткрыт (не исправлен или рецидив) |
| **Done** | Баг исправлен и проверен |
| **Archive** | Баг устарел или не актуален |
| **No bug** | Это не баг (отклонено) |
| **Fixed** | Баг исправлен (ожидает проверки) |

## 🎯 Severity (Критичность)

| Уровень | Описание |
|---------|----------|
| **Critical** | Блокирует основную функциональность, делает систему неработоспособной |
| **Major** | Серьезная проблема, но есть обходной путь |
| **Minor** | Незначительная проблема, не влияет на основной функционал |
| **Trivial** | Косметические проблемы (опечатки, отступы и т.д.) |

## 📊 Priority (Приоритет)

| Уровень | Описание |
|---------|----------|
| **High** | Требует немедленного исправления |
| **Medium** | Нужно исправить в ближайшее время |
| **Low** | Можно исправить позже |

## 🔍 Регрессионное тестирование

### Когда проводить:
- После каждого нового билда
- После исправления критических багов
- Перед релизом
- После внесения значительных изменений в код

### Что проверять:
- Основную функциональность (smoke-тесты)
- Ранее найденные и исправленные баги (проверка на рецидив)
- Смежные области, которые могли быть затронуты изменениями

## 🎲 Генератор тестовых данных

### Запуск интерактивной консоли:
```powershell
python scripts/test_data_generator.py
```

### Возможности:
- **👥 Генерация пользователей** - полные данные пользователя (имя, email, телефон, пароль, баланс)
- **⚔️ Генерация игровых персонажей** - с характеристиками, уровнями, редкостью
- **📧 Генерация email адресов** - с настройкой использования реальных имен
- **🔑 Генерация паролей** - слабые/сильные, с настройкой параметров
- **📱 Генерация телефонов** - с выбором кода страны
- **💰 Генерация цен** - с настройкой диапазона
- **📅 Генерация дат** - случайные, даты рождения, будущие
- **🔧 Произвольные данные** - выбор комбинации полей
- **💾 Экспорт** - JSON и CSV форматы

### Настройки:
- Выбор локали (RU/EN)
- Количество записей
- Диапазоны значений
- Форматы данных
- Длина строк

### Примеры использования:
```python
from scripts.test_data_generator import TestDataGenerator

generator = TestDataGenerator(locale="ru")

# Генерация 10 пользователей
users = generator.generate_users(10)

# Генерация 5 персонажей
characters = generator.generate_characters(5)

# Экспорт в JSON
generator.export_to_json(users, "test_users.json")

# Экспорт в CSV
generator.export_to_csv(users, "test_users.csv")
```

## 📄 Конвертер DOCX → Markdown

### Установка Pandoc (один раз, от имени Администратора):
```powershell
choco install pandoc
```

### Запуск:
```powershell
python scripts/docx_to_md.py
```

### Возможности:
- **Интерактивный режим** - выбор файла из списка, настройка опций
- **Командная строка** - `python docx_to_md.py file.docx`
- **Пакетная конвертация** - все DOCX файлы в папке за один раз
- **Извлечение изображений** - в отдельную папку `media/`
- **Статистика** - строки, слова, символы, изображения
